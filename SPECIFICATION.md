# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) НА РАЗРАБОТКУ СИСТЕМЫ vnxORACLE

**Версия документа:** 2.0  
**Дата:** 25.01.2026  
**Тип приложения:** Telegram Bot (Async)  
**Стек:** Python 3.10+, SQLite, Google Sheets API, OpenRouter/OpenAI API.

---

## 1. ЦЕЛЬ И НАЗНАЧЕНИЕ ПРОЕКТА

Разработка интеллектуального ассистента **vnxORACLE** в составе экосистемы vnxMATRIX. Бот предоставляет доступ к передовым LLM (GPT-4o, Claude 3.5), генерирует изображения, обрабатывает голосовые сообщения и предоставляет защищенное хранилище файлов внутри Telegram.

* **Ключевая особенность:** Атмосфера "Матрицы" / Киберпанка в текстах и интерфейсе.
* **Монетизация:** Подписочная модель (Tariffs), управление доступом через Google Таблицу.

---

## 2. АРХИТЕКТУРА СИСТЕМЫ

### 2.1. Структура проекта
Приложение реализовано по модульному принципу:

* `main.py` — Точка входа, инициализация ApplicationBuilder, регистрация хендлеров.
* `loader.py` — Инициализация синглтонов сервисов (DB, AI, Sheets) и логгера.
* `config.py` — Конфигурация, переменные окружения, тексты, настройки тарифов.
* `handlers.py` — Бизнес-логика обработки сообщений (Текст, Голос, Файлы, Коллбэки).
* `keyboards.py` — Верстка всех клавиатур (Reply и Inline).
* `services/` — Папка с модулями интеграций:
    * `database.py`: Прямая работа с SQLite (RAW SQL).
    * `ai_engine.py`: Обертка над OpenAI/OpenRouter API + Whisper + Pollinations.ai.
    * `sheets_manager.py`: Интеграция с Google Sheets (Auth/Tariff check).

### 2.2. Используемые технологии
* **Framework:** `python-telegram-bot` (версия 20+, async).
* **Database:** `SQLite` (локальное хранение `oracle.db`).
* **AI Provider:** `OpenRouter` (или OpenAI) для LLM, `Whisper` для STT.
* **Admin Panel:** Google Sheets (через `gspread` + `oauth2client`).
* **Image Gen:** `Pollinations.ai` API.

## 3. БАЗА ДАННЫХ (SCHEMA)

Используется реляционная модель. Файл БД: `oracle.db`.

### Таблица `users` (Пользователи и статистика)
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `user_id` | INTEGER (PK) | Telegram ID пользователя. |
| `total_tokens` | INTEGER | Общее количество потраченных токенов (Input + Output). |
| `username` | TEXT | (Опционально) Юзернейм. |

### Таблица `sessions` (Чаты/Диалоги)
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | INTEGER (PK AI) | Уникальный ID сессии. |
| `user_id` | INTEGER | Ссылка на users. |
| `title` | TEXT | Название чата (формируется по первому сообщению). |
| `created_at` | TIMESTAMP | Дата создания. |
| `is_active` | BOOLEAN | 1 — текущий активный чат, 0 — в архиве. |

### Таблица `messages` (История переписки)
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | INTEGER (PK AI) | Уникальный ID сообщения. |
| `session_id` | INTEGER | FK на sessions.id. |
| `role` | TEXT | `user` или `assistant`. |
| `content` | TEXT | Текст сообщения. |
| `model` | TEXT | Какая модель использовалась (напр. gpt-4o). |
| `timestamp` | TIMESTAMP | Время сообщения. |

## 4. АЛГОРИТМЫ И БИЗНЕС-ЛОГИКА

### 4.1. Авторизация и Проверка Тарифа (Gatekeeper)
Перед каждым действием (кроме `/start` и оплаты) бот проверяет доступ.
* **Источник правды:** Google Sheet, лист `Clients`.
* **Поиск:** Сканируются все строки с `telegram_id` пользователя.
* **Фильтрация:** Учитываются только строки, где `AI_Access` == `Active`.
* **Приоритет (Highest Win):**
    1.  Если найдена запись `NEO` → Тариф **NEO**.
    2.  Иначе, если `PRO` → Тариф **PRO**.
    3.  Иначе (пусто или START) → Тариф **START**.
* **Fail state:** Если активных записей нет → Блокировка действий, вывод Paywall.

### 4.2. Управление Контекстом (Memory Window)
Бот поддерживает контекст беседы, ограниченный тарифом:
* **START:** 10 сообщений.
* **PRO:** 30 сообщений.
* **NEO:** 60 сообщений.

*Алгоритм:* При запросе к API из БД извлекаются последние N сообщений сессии. `SYSTEM_PROMPT` добавляется всегда.

### 4.3. Сессии (Смена тем)
У пользователя только одна активная сессия (`is_active=1`).
Кнопка **"♻️ НОВЫЙ ЧАТ"**:
1.  Ставит `is_active=0` для всех старых сессий.
2.  Создает новую запись в `sessions`.
3.  Очищает контекст для LLM.

### 4.4. Меню "История Чатов"
Интерфейс на Inline-кнопках. Каждая строка содержит:
* Кнопка 1: `[Название чата (Дата)]` — загружает чат (context switch).
* Кнопка 2: `[❌]` — удаляет чат из БД (Hard delete).

### 4.5. Генерация изображений (Neural Canvas)
* **Триггер:** Сообщение начинается с `/img`.
* **Алгоритм:** Извлекается промпт → добавляются модификаторы ("highly detailed, cyberpunk") → GET-запрос к `pollinations.ai` → отправка фото.

### 4.6. Вечный Архив (The Vault)
* **Триггер:** Входящий `Document`, `Photo` (как файл) или `Audio`.
* **Действие:** Бот пересылает сообщение (`forward_message`) в закрытый канал-архив (ID берется из `ARCHIVE_CHANNEL_ID`).
* **Результат:** Файл сохраняется на серверах Telegram в отдельном канале, пользователь получает уведомление.

Вызывается кнопкой "🧠 Сменить модель":

* 🎤 **Аудио с ИИ** → Инструкция по голосовым.
* 🎨 **Дизайн с ИИ** → Инструкция по `/img`.
* 📹 **Видео/Хранитель** → Заглушки "В разработке".

## 6. ИНТЕГРАЦИИ И API

### 6.1. LLM Provider

* **Endpoint:** OpenRouter API.
* **Модели:**
* `START`: gpt-4o-mini
* `PRO`: gpt-4o
* `NEO`: claude-3.5-sonnet



### 6.2. Whisper (STT)

При получении Voice сообщения: Скачивание .ogg → Whisper API → Текст → Отправка в LLM.

## 7. ТРЕБОВАНИЯ К РАЗВЕРТЫВАНИЮ

* **Server:** Linux (Ubuntu 20.04+).
* **Daemon:** Systemd service (`vnx-oracle.service`) с авто-рестартом.
* **Environment (`.env`):**
```bash
BOT_TOKEN_ORACLE=...
OPENROUTER_API_KEY=...
GOOGLE_SHEET_ID=...
GOOGLE_CREDENTIALS_JSON=...
ARCHIVE_CHANNEL_ID=-100xxxxxxxxxx  # ID канала для файлов

```


* **CI/CD:** Ручное обновление (`git pull` + `oracle-restart`).
