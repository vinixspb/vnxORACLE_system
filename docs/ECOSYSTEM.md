## 🎯 Принципы системы

### 1. **Диалог > Интерфейс**
Пользователь не должен искать кнопки и формы — AI должен вести беседу и задавать правильные вопросы.

**Текущее состояние:**
- ✅ Trinity (web) — чистый диалог, без меню
- ⚠️ Telegram боты — пока много inline-кнопок (расписание, прайс)

**Целевое состояние:**
```
Пользователь: "Хочу записаться на стрижку"
Бот: "На какой день вам удобно? Можно сегодня в 15:00 или завтра утром"
[Кнопки появляются только если пользователь затрудняется ответить текстом]
```

---

### 2. **Омниканальность (Omnichannel Memory)**

Начал разговор на сайте → продолжил в Telegram → завершил сделку в приложении.

**Техническая реализация:**
- Единый `session_id` в localStorage (web) + Telegram user_id
- API синхронизирует историю между каналами
- База данных хранит полную цепочку касаний

**Пример флоу:**
```
1. Пользователь открыл vnxoracle.uk → Trinity спросила про задачу
2. Кликнул "Продолжить в Telegram" → session передан через deep link
3. В Telegram бот продолжил с того же места: "Вы говорили про автоматизацию поддержки..."
4. Заявка отправлена → менеджер видит ВСЮ историю с сайта
```

**Текущее состояние:** частично реализовано (web API готов, интеграция с TG в разработке)

---

### 3. **Фабрика ботов (Bot Factory)**

vnxoracle.uk — не просто маркетинговый сайт, а **конструктор AI-сотрудников**.

**Идеальный сценарий:**
```
1. Клиент заполняет диалог с Trinity: "Нужен бот для салона красоты"
2. Trinity задаёт вопросы: услуги, расписание, тон общения
3. На выходе → готовый бот разворачивается за 24 часа
4. Клиент получает: Telegram + web-чат + админ-панель
```

**Текущая реализация:**
- Шаблон `ai-worker-template` проверен на 5+ проектах
- Клонирование занимает 1-2 недели (ручная настройка)
- Цель: автоматизировать через Trinity как "конфигуратор"

---

### 4. **Саморазвивающаяся система**

AI-сотрудник должен учиться без вмешательства разработчика.

**Механизмы:**
- **ETL-парсинг:** бот читает сайт клиента, обновляет базу знаний сам
- **Auto-sync:** изменение прайса на сайте → бот узнаёт автоматически
- **Feedback loop:** каждый диалог улучшает промпты через анализ

**Пример:**
```
Санаторий добавил новую процедуру "Криосауна" на сайт
→ ETL-парсер подхватил изменение
→ Бот начал предлагать криосауну клиентам БЕЗ редеплоя
```

## 🔗 Связь компонентов

### ai-worker-template (Core)
- Расположение: `/opt/vnxORACLE_aibot/ai-worker-template/`
- Роль: базовый шаблон для всех ботов
- Содержит: AI Engine, Rate Limiter, Session Manager, Formatting

### vnxoracle.uk (Showcase)
- Расположение: `/opt/vmxORACLE_site/` + API `/opt/vnxORACLE_aibot/web_api/`
- Роль: витрина + продажи + фабрика
- Trinity: использует тот же AI Engine, что и клиентские боты

### Клиентские боты (Instances)
- Каждый — форк `ai-worker-template` с кастомизацией:
  - Промпты (tone of voice, специфика отрасли)
  - Интеграции (CRM, планировщик, платежи)
  - Каналы (Telegram обязательно, web-чат опционально)

## 🛠️ Технический стек (единый для всех)

- **Backend:** Python 3.12 + FastAPI + asyncio
- **AI:** OpenRouter API (мультимодельный доступ)
- **Telegram:** aiogram 3.x
- **Web:** React + Vite + Motion (Framer Motion)
- **Database:** SQLite (dev) → PostgreSQL (prod, будущее)
- **Deploy:** systemd services на Debian 12 (MATRIXde-n1)
- **Reverse Proxy:** Caddy (MATRIXde-n1) + nginx (альтернативно)
- **DNS:** Cloudflare (Proxied для сайтов, DNS-only для API)

## 🎨 Философия UX: "Intelligence without Interface"

> "Лучший интерфейс — тот, которого нет. AI должен понимать намерение, а не ждать клика."

### Антипаттерны (чего избегаем):
- ❌ Меню из 10 кнопок "Выберите категорию"
- ❌ Формы с 15 полями "Заполните всё сразу"
- ❌ FAQ как список: "Прочитайте 50 пунктов и найдите ответ"

### Правильный подход:
- ✅ Бот задаёт вопросы последовательно, как живой человек
- ✅ Кнопки появляются только когда клиент НЕ знает, что ответить
- ✅ Контекст сохраняется: "Вы вчера спрашивали про массаж — готовы записаться?"
